# Story 15.7: Integracao real — Configuracoes e Avaliacao (quiz analytics)

Status: Review

## Objetivo

Substituir os dados fabricados de `src/pages/configuracoes.tsx` e
`src/pages/avaliacao.tsx` por leitura/escrita real dos contratos admin ja
entregues pelo Epic 14, usando a sessao CRM do Supabase do app e
`VITE_API_URL` da Story 15.2.

## Contexto

Stories 15.1 e 15.2 estao `Done`: contas CRM autenticam diretamente no
Supabase do app por ambiente, com `role = "admin"` no token; o dashboard ja
tem `src/lib/supabase-crm.ts` e `VITE_API_URL` para chamar o worker. Stories
15.3 e 15.4 fecharam o gate CRM de sidebar/rota.

O Epic 15 define esta story como a integracao real de Configuracoes e
Avaliacao. O worker ja expoe os contratos necessarios em
`worker/src/routes/admin/settings.ts`, `lastlink-product-map.ts` e
`suggestions.ts`; os contratos read-only de quiz/settings vivem nas RPCs
`admin_*` entregues pelo Epic 14. Esta story consome esses contratos sem
criar rota, contrato `admin_*`, migration ou backend paralelo.

`avaliacao.tsx` exige atencao especial: os dados fabricados nao usam apenas
prefixo `MOCK_`. As constantes `QUIZ_INICIO_QUESTIONS`,
`QUIZ_REAVALIACAO_QUESTIONS`, `RESPOSTAS_USUARIOS`, `PERGUNTAS_RESUMO`,
`PERFIL_FINANCEIRO_DATA`, `OBJETIVOS_DATA`, `EXPERIENCIA_DATA`,
`PLANOS_DATA`, `ULTIMAS_RESPOSTAS`, `DESISTENCIA_POR_PERGUNTA` e
`ANALISE_PERGUNTAS` simulam dados reais e devem ser removidas ou
substituidas por estado derivado dos contratos.

## Escopo

1. `configuracoes.tsx`
   - Ler `admin_app_settings_current`.
   - Ler `admin_lastlink_product_map`.
   - Persistir links/validade via `PATCH /admin/settings`.
   - Persistir prazo global via `PATCH /admin/settings/reassessment`.
   - Persistir label de produto via
     `PATCH /admin/lastlink-product-map/:productId`.
   - Remover `MOCK_CONFIG`, `MOCK_REAVALIACAO_DIAS`,
     `MOCK_LAST_APPLIED_TEXT` e timers de loading/sucesso fake.
2. `avaliacao.tsx`
   - Ler respostas por usuario via `admin_quiz_responses_by_user`.
   - Ler detalhe via `admin_quiz_response_detail`.
   - Ler perguntas/opcoes agregadas via `admin_quiz_question_stats`.
   - Ler resumo via `admin_quiz_analytics_summary`.
   - Ler sugestoes via `admin_suggestions_list`.
   - Classificar sugestao, se exposta, via
     `PATCH /admin/suggestions/:id/status`.
   - Remover constantes fabricadas sem prefixo `MOCK_` e estados
     artificiais.
3. Implementar estados reais de loading, vazio, erro e salvamento nas duas
   paginas, preservando os estados forcados por query string
   (`loading=1`, `empty=1`, `canEdit=false`) usados por catalogo/testes
   quando ja existirem.
4. Remover qualquer filtro redundante "apenas quem terminou o quiz", se
   ainda existir. Story 14.9 confirmou que `quiz_responses` so grava
   submissao completa.

## Dev Notes

- `admin_app_settings_current()` retorna `app_name`,
  `trinca_product_ids`, `elite_product_ids`, `trinca_validity_days`,
  `elite_validity_days`, `upgrade_url`, `renewal_trinca_url`,
  `renewal_elite_url`, `support_url`, `reassessment_days`,
  `depends_on_future_table` e `blocked_by`.
- `PATCH /admin/settings` aceita payload parcial com
  `upgradeUrl`, `renewalTrincaUrl`, `renewalEliteUrl`, `supportUrl`,
  `trincaValidityDays` e `eliteValidityDays`. URLs devem ser `http(s)` ou
  `null`; validade aceita inteiro `1..3650`.
- `PATCH /admin/settings/reassessment` aceita
  `{ reassessmentDays: number }`, inteiro `1..365`.
- `admin_lastlink_product_map(p_tier, p_is_upsell)` retorna
  `product_id`, `tier`, `is_upsell`, `label`. A rota de escrita de produto
  so permite editar `label`; nao tentar editar `productId`, `tier` ou
  `isUpsell`.
- `admin_quiz_responses_by_user` ja retorna o payload `respostas` suficiente
  para derivar badges visuais de idade/sexo/experiencia sem filtro novo.
- `admin_quiz_question_stats(p_quiz_type, p_question_key, p_limit)` le o
  rollup `admin_quiz_question_rollup`; nao agregar client-side sobre
  `quiz_responses` bruto.
- `admin_quiz_analytics_summary()` nao contem metricas de funil, abandono ou
  tempo medio; se a UI atual depender disso, remover/adiar esse bloco em vez
  de manter dado fabricado.
- `admin_suggestions_list(p_user_id, p_status, p_before_created_at,
  p_before_suggestion_id, p_limit)` retorna `status` com valores
  `nova`, `revisada`, `implementada`.
- `PATCH /admin/suggestions/:suggestionId/status` aceita somente
  `{ status: "nova" | "revisada" | "implementada" }`, exige
  `Idempotency-Key` e grava `admin_audit_log`.
- Se a sub-aba "Quiz" de `avaliacao.tsx` for mantida, ela deve ser leitura
  derivada dos contratos de stats/resumo; nenhum toggle de visibilidade ou
  editor deve persistir localmente porque editor de quiz esta fora de
  escopo.
- A sub-aba "Relatorios" dentro de `avaliacao.tsx` hoje mostra metricas
  cortadas do Epic 14. Nao reabrir backend; nao manter valores fabricados
  disfarçados de real.
